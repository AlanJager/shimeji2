# shimeji2 动作编辑器

本地浏览器工作台，支持整帧动画、多部件关键帧、触摸区域和互动规则。工程保存源素材、部件层级、关节与关键帧；导出 ZIP 可以在本次带编辑器运行时的 macOS 构建中直接导入和使用。

## 启动

包含编辑器的 macOS DMG 中，直接将 `shimeji-editor.app` 拖到 Applications
并双击即可，无需安装以下开发依赖。菜单栏“编辑器”可重新打开浏览器或退出
后台服务，关闭标签页不会结束服务。退出前保存工程；VRM/VRMA 另存 3D 工程。
若已有开发服务占用 4317，可先退出它，或以
`open -a shimeji-editor --args --port 4318` 使用独立端口（浏览器草稿按端口隔离）。
一体 DMG 的构建方法见 `docs/release.md`。

不安装 Python 时，用 Rust 二进制 `shimeji-editor`。它在本机完成解码和导出，只监听 127.0.0.1，并把上面的页面交给浏览器。仓库里可执行 `cargo build -p shimeji-editor --release`，然后 `target/release/shimeji-editor --open`。发给别人时，压缩包里带有页面、内置 shime 和素材目录，双击「启动编辑器」即可，对方不需要 Python 或 Pillow。Windows 包由 `scripts/build-editor-windows.sh` 交叉编译。线上 Vercel 仍使用 Python。

需要 Python 3.9+ 和 Pillow 的是开发服务和 Vercel；动图与图集解码在本机 Python 服务中完成，WebP 需要 Pillow 带有 WebP 支持（本机验证版本为 12.3.0）。3D 库已随源码在 `vendor/` 中本地打包，使用时无需 npm 或 CDN。服务仅监听 127.0.0.1，不提供整个仓库的文件访问。

```sh
./scripts/editor.command
# Windows 解压后双击 scripts\editor.bat，或仓库里的同名文件
# 或不自动打开浏览器
python3 tools/editor/server.py
# 如缺少 Pillow
python3 -m pip install Pillow
```

默认地址 http://127.0.0.1:4317；终端 Ctrl+C 退出。`--port 4318` 可改端口。`?session=editor-v2` 使用单独的自动保存空间，可以体验新示例而保留旧草稿。宽屏三栏显示，窄窗口的属性区位于工作区下方。

## 部署到 Vercel

把这个 Git 仓库连接到 Vercel，项目根目录保持仓库根目录。根目录的 `pyproject.toml` 会让 Vercel 用 Flask 打开同一套页面和接口，不需要另外搬文件。

线上和本机用的是同一份编辑器，限制不同：

- 单次上传和返回不超过 4 MB。更大的素材或工程请继续用本机服务。
- 素材目录只展示来源说明，服务器不代下载角色包。
- 工程保存在各人的浏览器里，服务器不保存角色、设置或上传的原文件。
- 只有打开这个站点的页面能调用接口；别的网站不能拿它做转发。

## 部署到 EdgeOne Makers

在腾讯云导入 GitHub 仓库 `AlanJager/shimeji2`，分支 `main`。根目录用 `./`，构建命令 `sh scripts/prepare-edgeone.sh`，输出目录 `edgeone-public`。不要套用 Next 或其他前端框架预设。`edgeone.json` 写的是同一组配置。

页面和内置 shime 图片由静态目录提供。`/api/*` 由 `cloud-functions/api/index.py` 这个 Python 3.10 函数处理，限制与 Vercel 相同：单次 4 MB，素材目录不代下载角色包。本机大文件仍用 `shimeji-editor` 二进制。构建日志里应出现 `Found` 和 `Python functions`，随后才会安装 Pillow。

## 制作多部件动作

1. 选择“部件 · 轻轻呼吸”示例。头部挂在身体上，每个部件都有自己的动画轨道；示例图片是原白色 shime 的编辑副本，没有改动上游文件。
2. 点击素材或导入 PNG 添加部件。导入向导可确认整组缩放、定位点和目标锚点，默认仅缩小超出画布的图片，生成透明 128×128 的编辑副本，原文件不变。也可以从动作属性把新动作切换成“多部件动画”。
3. 选中部件，在“部件”面板设置父级、关节位置、显示状态和遮挡层次。部件按列表顺序绘制；父级变换带动子级，隐藏父级也会隐藏子级。
4. 拖动时间游标，再修改位置、角度、缩放、不透明度、遮挡顺序、可见性或素材，会自动记录当前动作的关键帧。遮挡顺序数字更大的部件画在上面；不透明度会烘焙进导出的 PNG。也可以按“记录当前关键帧”，或在预览中拖动选中部件。选择“部件默认姿势”则编辑没有动画轨道时使用的姿势。
5. 给循环动作在结尾记录与开头一致的姿势，例如 0 tick 0°、25 tick 15°、50 tick 0°。数值线性插值；素材与显示状态在关键帧处切换。
6. 在动作属性中设定默认动作。现有整帧动画的拖排、帧复制、时长与偏移编辑仍可使用。

每个部件可以自由命名，不要求固定身体结构；不会自动拆图、补画、绑定网格或生成缺失动作。这是分层图像变换编辑器，不是 Live2D 变形建模器。

动作库上方“＋ 站着跳舞”可添加白色 shime 的原地摇摆舞：头部反向跟随身体，40 tick / 1.60 秒循环。添加为独立整帧动作，可继续改时长、倒序或绑定互动；已有工程无需重置示例。新示例工程另保留该动作的身体/头部关键帧版本。

## 制作序列帧动画

点击“导入素材”或拖入文件，支持 PNG、GIF、APNG（包括扩展名为 `.png` 的动画）、静态/动态 WebP、JPEG、ZIP 图片序列，以及 Aseprite / LibreSprite 的 `.ase` / `.aseprite`、Piskel 的 `.piskel`、Pixelorama 1.x 的 `.pxo`。这些工程在编辑器内解码，不必先导出。Aseprite 可见的普通图层按单元格叠成整帧，标签变成动作，slice 的外框变成触摸区域，pivot 在只新增一个部件时写成锚点。Piskel 按帧率展开，靠后的图层画在上面，隐藏帧不导入。Pixelorama 的动作标签会变成动作，帧时长按工程帧率换算；瓦片、分组、三维和音频图层跳过。瓦片图层、参考层和九宫格中心不导入；非普通混合模式按正常透明度叠加。索引色或 Pixelorama 0.x 工程请先在原软件里另存或导出 PNG。把文件拖到某一帧上，会插入到该帧之后。“文件夹”可以直接选择图片目录，按自然文件名顺序排列（1、2、10）；只忽略明确识别的 macOS 元数据文件，其他不支持的文件会报错。一张静态精灵图可选择“按网格切分”，设置格子宽高、起始偏移、间距、逐行/逐列顺序和帧数；预览会指出当前切分位置。

动图会先处理透明叠加和前帧清除，恢复成完整逻辑画布帧。默认保留原始帧时长，按片段累计对齐 40 ms，每帧至少 1 tick；导入前显示原始与调整后的总时长。可以改为统一时长，循环方式可沿用素材或手动选择。有限重复次数只能导入为单周期，界面会说明；JPEG 保留其原有不透明背景，不会自动抠图。

Aseprite 导出的一个 JSON 和对应 PNG 可以一起选择，也可放在同一个 ZIP 中；支持 array/hash 帧数据、裁切偏移、旋转存储和原始画布尺寸。可选一个标签，或按全部标签分别生成动作，支持正序、倒序和往返方向。标签共用素材图片，源素材组保持完整顺序；动画和图集不会被误叠成一组静态部件。

所有帧使用相同缩放比例，可选仅缩小适配、原始像素或指定比例。源定位点支持底部居中、中心和左上角，整组对齐到同一个目标锚点；超出画布会提示裁切。没有图集定位数据的独立裁切帧仍需自己确认定位，编辑器不会推断身体结构。选择每帧停留 tick（1 tick = 40 ms），追加到当前动作或新建动作。处于部件动作时，静态图片批次可以“添加到当前部件图层”。导入全部完成才更新工程，取消不会留下半组素材，一次撤销即可撤回本次导入。相同的归一化 PNG 会共用一个素材 ID。

时间轴支持 Shift 连选、⌘/Ctrl 多选和空白处拖框。可拷贝并跨动作粘贴、复制一份、删除、倒序、往返、统一每帧毫秒数和整段调速；连续选区还可以“建成动作”，方向为正序、倒序或往返。往返要求连续选区，`ABC → ABCB` 不重复端点。播放速度 0.5× / 2× 只改变预览，不改每帧 tick。选中一帧后可以“补这一帧”：铅笔、橡皮、填充、吸管、水平对称和锁透明。若这张图还被别的帧或部件使用，写回时只断开当前帧。快捷键为 ⌘/Ctrl+A 全选、C 拷贝、V 粘贴、D 复制一份、Delete 删除、Z 撤销。打开其他工程会清空内部剪贴板。时长对齐 40 ms 网格；整段调速保持取整后的总 tick 数，每帧至少 1 tick，超出上限会拒绝。

“循环所选片段”只用于编辑模式下的连续选区播放，不改变导出动作；若要让选区成为独立动作，可拷贝后新建动作再粘贴，删除新动作中不需要的初始帧。

## 整理素材库

每次导入形成一个素材组，显示素材张数、逻辑帧数、使用数量和来源。展开查看图片，按名称、分组或来源搜索，可筛选当前动作使用或未使用素材。旧工程会自动推导内置、动作和未分组素材，查看时不会改写工程。

单击只选中，双击或“添加所选”才追加；Shift 连选、⌘/Ctrl 多选可以批量添加。分组预览按组内实际顺序与时长播放，也能把整组追加到当前整帧动作。分组、素材可改名，所选图片可另建分组；解散分组保留图片。

选择一张素材后“替换图片”，经过同样的缩放与定位预览，确认后保留素材 ID、名称和全部引用，因此动作时长、部件和互动规则不变。共享这张图片的动作会一起更新。删除只允许未被动作、部件或关键帧使用的图片；“清理未使用”也检查全部这些引用，并同步移除空分组。整理、替换和删除都能撤销。

普通工程保存的是归一化 PNG、素材组、量化后的时长和来源文件名；不会嵌入原始 GIF、WebP、ZIP 或图集文件，请保留原文件。ZIP 和图片均在内存中处理，不向磁盘解压。

单张源图片最多 8 MiB、4096 像素边长，ZIP 最多 16 MiB，图集 JSON 最多 1 MiB；一批最多 256 帧、16M 解码像素和 16 MiB 中间 PNG。ZIP 只接受图片序列或一份 Aseprite 图集，完整经典 Shimeji 包仍走素材目录或原生导入。分组、重命名和来源数据是编辑器元数据，导出运行时继续只使用 PNG 和动作帧。

## 前后帧参照和原尺寸预览

“洋葱皮”将前后姿势着色叠在当前姿势后面。参照设置可调前后各 1–3 帧、透明度、颜色及循环边界；整帧动作按实际相邻帧取样，部件动作按最多 5 tick 间隔取样。参照不接收鼠标事件，互动模式自动隐藏。

右侧“原尺寸”固定显示 128×128 CSS 像素，与放大编辑区使用同一张图片、偏移或部件姿势。编辑区默认 150%，可独立选择 100%–250%；原尺寸视图保持 100%。两种辅助视图、选区和预览循环均不会写入工程或导出的图片。

## 从 VRM 制作动画

顶部“3D 工作室”可打开本机 `.vrm`（0.x / 1.0）人形模型，选择待机、呼吸、挥手、跳舞，或导入 `.vrma` 动作。模型、纹理和动作留在本机浏览器中处理。设置表情、镜头方向、俯仰、缩放、垂直位置、动作起点与长度后，先播放或拖动时间游标检查构图；128×128 视图显示实际导出尺寸。

“烘焙并添加动作”按每 tick 40 ms 输出透明 PNG，作为独立整帧动作追加到当前工程。镜头在整段动画中固定，不逐帧重新居中。可继续使用时间轴操作、设置默认动作或绑定互动规则，一次撤销可移除整次烘焙。默认关闭头发弹簧模拟；启用时使用固定步长模拟。触及画布边缘会提示，可缩小镜头后重新烘焙。

**请在工作室单独“保存 3D 工程”**，它包含原始模型、可选动作和镜头配方。普通“保存工程”和桌宠 ZIP 只保存烘焙的 PNG、配方与源文件哈希，不能恢复原始 3D 模型。关闭工作室释放 GPU 资源，在当前页面重开会保留已导入素材；刷新页面前应保存 3D 工程。

支持自包含二进制 GLB，仅接受内嵌 PNG/JPEG 纹理。模型上限 32 MiB、20 万实例化顶点、100 万绘制元素、512 节点、纹理总计 32M 像素；展开的 morph 数据限制为 64 MiB CPU 缓冲（GPU 另需同量），共享引用也累计预算。动作上限 8 MiB；烘焙 1–250 tick（0.04–10 秒），还受现有工程 256 张素材和 64 个动作上限约束。外部资源 URI、Draco/meshopt 等压缩扩展不支持。浏览器需要 WebGL 2。桌面播放使用 PNG 序列帧，未加入实时 3D、模型建模或逐骨骼关键帧编辑器。

维护依赖时进入 `tools/editor` 运行 `npm ci --ignore-scripts && npm run build:vrm`。版本由 `package-lock.json` 固定，构建同步生成库、许可证与 SHA256 清单；不要提交用户模型或测试模型。

## 互动规则

在“互动规则”中绘制矩形区域，配置事件、区域、前置动作、目标动作、冷却 tick 和优先级。支持点击、抚摸、进入区域、开始拖拽、松开拖拽、无操作 5 秒。

规则需要同时满足启用、事件、区域、前置动作与冷却条件。优先级高的先执行，同优先级按列表顺序；未选中的规则不消耗冷却。勾选“播完一轮回到默认”时，循环目标也只播放一轮。单次动作本身会回到默认；循环动作每轮结束释放优先级。

触摸区域固定在角色的 128×128 逻辑画布中；后绘制区域在上层。抚摸需要在区域内移动鼠标；桌面运行时排除静止鼠标下由动画变化造成的假移动。真正拖拽后不会额外触发点击。

编辑模式仅预览动画；“测试互动”运行规则。底部事件记录用于查看匹配结果。桌面运行时每只角色有独立的状态和冷却。暂停/隐藏/系统睡眠不推进规则时间；时钟恢复后不会追赶丢失的 tick。

## 保存、导出与导入

“保存工程”下载 JSON，包含自定义 PNG 和全部动画数据；“打开工程”恢复它，支持旧 v1 工程。自动保存按浏览器、端口和 session 隔离；空间不足时请保存文件。

导出的 ZIP 包含：

- `editor-project.json`：可继续编辑的完整源工程，包括部件、层级、关节和关键帧。
- `editor-runtime.json`：有版本号的动作时序、区域和规则，由新运行时直接执行。
- `conf/actions.xml`、`conf/behaviors.xml`：经典引擎实际播放的动作和默认行为。
- `img/`：原素材与合成后的透明动画帧，另有素材来源与许可说明。

多部件动作按固定 40ms tick 合成为 128×128 帧，不逐帧重新居中，连续相同帧可以无损合并。运行时仍用现有纯 Rust PNG 解码器和渲染管线。**要执行互动规则，必须使用本次带编辑器运行时的新 macOS 构建；旧构建只能播放动画。** 当前没有给 Windows shell 接入新的输入路由。

在新构建的“设置 → 宠物”中导入 ZIP、启用角色即可；以后重新导出同名包，选择替换。导入校验会拒绝损坏或与动画不符的运行时清单，不会悄悄丢弃规则。源部件保留在工程里，桌面播放的是导出时的合成帧。

开发时也可以在隔离配置中直接导入并启动：

```sh
SHIMEJI_TRACE_MOTION=1 cargo run -p shimeji-macos -- \
  --pack /absolute/path/to/export.zip \
  --profile /tmp/shimeji-editor-review \
  --agent-home /tmp/shimeji-editor-review/agent-home --seconds 180
```

## 范围与限制

逻辑画布固定 128×128。最多 32 部件、64 动作、每条轨道 256 关键帧；单个部件动作最多 1000 tick，整个工程的部件动画最多 2000 tick（80 秒）。这些上限让合成时间与解码内存有界；较长内容可以拆工程。整帧动作仍支持原有帧时长。

支持部件位移、旋转、缩放、隐藏、素材切换和父子关系；不支持柔性网格、骨骼 IK、音频轨、运动物理参数编辑或任意经典包的完整反向导入。现有旧包的行为语义保持原样。

## 从现有素材开始

顶部“素材目录”提供搜索、类型筛选、原站链接、实际包结构和使用说明。首批 8 个来源中，白色 Shime、初音未来、博丽灵梦提供固定版本的动作提取。只有主动点击导入时才下载归档；下载受 64 MiB 上限约束并核对 SHA256。本机内容缓存位于 gitignored 的 `output/material-catalog/cache/`。

这三个包发布的是完整 PNG 帧，不包含头、身体、手等独立图层。读取后保留可编辑的整帧动作片段与来源信息，可以修改帧时长、组合新动作、添加自己的 PNG 部件和互动规则。编辑器不还原原包的表达式、移动物理和完整行为状态机；需要原样使用时，在新 macOS 构建的“设置 → 宠物 → 浏览素材来源…”中下载导入，或以 `--materials` 直接打开该窗口。

Live2D 官方样例单独标明为结构对照，当前不能导入。纹理图集还需要 MOC3 网格、UV、遮挡和参数，不能直接当作独立 PNG 部件组。详细核验见 `docs/research/material-sources-2026-11-05.md`。
